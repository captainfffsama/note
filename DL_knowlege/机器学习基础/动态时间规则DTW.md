## Turn 1

### 🤖 助手

动态时间规整（**Dynamic Time Warping, DTW**）非常适合用来评估两条机器人轨迹的相似度。因为机器人轨迹（如末端执行器的位置、关节角随时间的变化）通常具有**时间非线性**——即便两个动作完全相同，执行的速度、停顿或加速度也可能不同。DTW 能够通过对时间轴进行弯折（Warping），找到两条序列在**形变最小**情况下的最佳匹配点。

下面为你梳理如何将 DTW 落地应用于机器人轨迹距离计算。

## 1. 核心数学表达与设计

计算两条轨迹 $X = (x_1, x_2, \dots, x_N)$ 和 $Y = (y_1, y_2, \dots, y_M)$ 之间的 DTW 距离，包含三个核心要素：

### ① 状态表示（帧向量 $x_i$ ）

机器人轨迹的每一帧通常是一个多维向量。常见表示方法：

- **笛卡尔空间轨迹**： $x_i = [p_x, p_y, p_z]^T \in \mathbb{R}^3$ （仅位置）或包含姿态（四元数/欧拉角）。
- **关节空间轨迹**： $x_i = [\theta_1, \theta_2, \dots, \theta_k]^T \in \mathbb{R}^k$ （ $k$ 为自由度/关节数）。

### ② 帧间距离度量（点对点 Cost）

计算第 $i$ 帧 $x_i$ 和第 $j$ 帧 $y_j$ 之间的距离 $d(x_i, y_j)$ ：

- **关节角/笛卡尔位置**：直接采用**欧式距离** (Euclidean Distance)： $d(x_i, y_j) = \Vert{}x_i - y_j\Vert{}_2 = \sqrt{\sum_{k} (x_{i,k} - y_{j,k})^2}$
- **包含三维姿态（四元数 $q_1, q_2$ ）**：利用四元数内积度量旋转差异： $d_{rot}(q_1, q_2) = 1 - \vert{}\langle q_1, q_2 \rangle\vert{}$ 此时总距离可表示为位置欧氏距离与姿态距离的加权和： $d_{total} = d_{pos} + w \cdot d_{rot}$ 。

### ③ 动态规划求解代价矩阵（DTW Matrix）

构建大小为 $N \times M$ 的累积距离矩阵 $D$ ，递归递推公式为：

$$
D(i, j) = d(x_i, y_j) + \min \begin{cases}  D(i-1, j) & \text{(伸展/停留)} \\  D(i, j-1) & \text{(缩短/跳过)} \\  D(i-1, j-1) & \text{(按顺序匹配)}  \end{cases}
$$

边界条件为 $D(0, 0) = d(x_1, y_1)$ 。最终的 DTW 距离为 $D(N, M)$ 。

## 2. Python 实战代码示例

在工程落地中，可以直接利用 `fastdtw` 或 Python 科学计算库（如 `scipy` / `tslearn`）进行高效计算。以下为一个基于 NumPy 的轻量级高维轨迹 DTW 实现：

```python
import numpy as np

def compute_robot_dtw(traj_A, traj_B):
    """
    计算两条机器人轨迹之间的 DTW 距离
    
    :param traj_A: np.ndarray, 形状为 (N, D)，N 为时间步数，D 为特征维度(如 6 关节角/3 维 Cartesian)
    :param traj_B: np.ndarray, 形状为 (M, D)，M 为时间步数
    :return: dtw_distance (float), Cost Matrix D (np.ndarray)
    """
    N, D_a = traj_A.shape
    M, D_b = traj_B.shape
    assert D_a == D_b, "两条轨迹的特征维度必须一致"

    # 1. 计算两两帧之间的距离矩阵 Cost Matrix d(i, j)
    # 使用广播机制高效计算欧式距离
    diff = traj_A[:, np.newaxis, :] - traj_B[np.newaxis, :, :] # (N, M, D)
    dist_matrix = np.linalg.norm(diff, axis=2)                   # (N, M)

    # 2. 初始化累积代价矩阵 D
    D = np.zeros((N, M))
    D[0, 0] = dist_matrix[0, 0]

    for i in range(1, N):
        D[i, 0] = D[i-1, 0] + dist_matrix[i, 0]
    for j in range(1, M):
        D[0, j] = D[0, j-1] + dist_matrix[0, j]

    # 3. 动态规划填充矩阵
    for i in range(1, N):
        for j in range(1, M):
            D[i, j] = dist_matrix[i, j] + min(
                D[i-1, j],    # traj_A 匹配 traj_B 的同一帧（A 停顿/伸展）
                D[i, j-1],    # traj_B 匹配 traj_A 的同一帧（B 停顿/伸展）
                D[i-1, j-1]   # 两者同时前进一步
            )

    # 4. 归一化 DTW 距离（消去轨迹长度差异带来的影响）
    dtw_distance = D[N-1, M-1] / (N + M)
    return dtw_distance, D

# --- 测试示例 ---
if __name__ == "__main__":
    # 假设 Traj A 有 100 个时间步，Traj B 有 120 个时间步，均为 6 自由度关节角轨迹 (Rad)
    t_a = np.linspace(0, np.pi, 100)
    t_b = np.linspace(0, np.pi, 120)
    
    # 模拟两条形状类似但时序/速度不同的轨迹
    traj_A = np.sin(np.vstack([t_a]*6).T) 
    traj_B = np.sin(np.vstack([t_b**1.1]*6).T) # 引入时间弯折
    
    dist, _ = compute_robot_dtw(traj_A, traj_B)
    print(f"Normalized DTW Distance between trajectories: {dist:.4f}")

```

## 3. 机器人轨迹计算中的工程建议

在真实场景（如示教再现、轨迹跟踪评价、动作分类）中，应用 DTW 时有几个关键技巧：

1. **维度归一化 (Feature Normalization)** 如果特征向量包含了不同物理单位的数据（如 `[x, y, z]` 单位是米，`[yaw, pitch, roll]` 是弧度，或叠加了速度 `[vx, vy, vz]`），不同量纲会严重偏置距离计算。建议事先对各个维度做 standard scaling（Z-score 归一化）或最大最小值缩放。
2. **限制时间弯折窗口 (Sakoe-Chiba Band / Itakura Parallelogram)** 标准的 DTW 会尝试全局寻找最佳对齐，但如果时间轴偏离太大，可能会把动作开头的帧与动作结尾的帧匹配起来，这在物理上毫无意义。
  - **解决方案**：引入约束窗口（如 `window_size = 10` 步），限定 $\vert{}i - j\vert{} \le w$ 。这不仅能避免非物理的越界匹配，还能将时间复杂度从 $O(NM)$ 降低到 $O(N \cdot w)$ 。
1. **归一化处理 (Distance Normalization)** 因为 $D(N, M)$ 累积代价受轨迹总步长 $N$ 和 $M$ 的影响，对比不同长度的轨迹对时，**务必使用平均对齐路径长度进行归一化**（通常除以 $N+M$ 或匹配路径的总步数 $K$ ），否则较长的轨迹对默认会算出更大的绝对距离。
2. **导数 DTW (Derivative DTW / DDTW)** 如果两条轨迹的绝对位置有偏移，但**运动趋势/形状**完全相同，标准 DTW 可能会误判。此时可以计算**轨迹的一阶导数（速度 Profile）**，用导数序列代入 DTW 进行匹配。

## 一、 用“双人舞蹈”通俗理解 DTW

假设你要评估两个舞蹈演员（机器人 A 和机器人 B）做**同一个抬手动作**相似度有多高：

- **机器人 A** 动作快，用了 **3 秒**（生成了 3 帧画面）。
- **机器人 B** 动作慢，或者中间停顿了一下，用了 **5 秒**（生成了 5 帧画面）。
如果按照最直观的**按时间对齐**（第 1 秒对第 1 秒，第 2 秒对第 2 秒）：

> 机器人 A 第 2 秒已经把手抬到顶峰准备放下了，而机器人 B 第 2 秒才刚刚抬到一半。如果你直接比对第 2 秒画面，会觉得“这两个动作一点都不像”。
**DTW 做的事情，就是允许时间“伸缩（Warping）”**：
它不再硬性规定“同一时刻对比同一时刻”，而是帮你在时间轴上做弹性调整——**让机器人 A 的第 2 秒（最高点），去匹配机器人 B 的第 3 秒（最高点）**。
DTW 就像是在找“两个动作最神似的状态匹配”：

- 动作快的某一帧，可以**拉长**去匹配动作慢的连续几帧；
- 动作慢的连续几帧，可以**压缩**去匹配动作快的同一帧。
在找到这种“最佳匹配”之后，把每一对匹配点的空间物理差距加起来，算出的最小值，就是两条轨迹的 **DTW 距离**。**距离越小，说明动作越相似。**

## 二、 长度不一致时，DTW 是如何处理的？

如果轨迹 A 有 3 个点，轨迹 B 有 5 个点，DTW 是怎么把它们“对齐”并算距离的？

这就需要用到 DTW 的核心工具：**网格与动态规划（Dynamic Planning）**。

### 1. 铺一张“对齐网格”

我们将轨迹 A 作为横轴（3 个点： $A_1, A_2, A_3$ ），轨迹 B 作为纵轴（5 个点： $B_1, B_2, B_3, B_4, B_5$ ）。

这就构成了一个 $3 \times 5$ 的格子网格。

```
B5 |   |   |   |
B4 |   |   |   |
B3 |   |   |   |
B2 |   |   |   |
B1 |   |   |   |
   +-----------
     A1  A2  A3

```

网格里每一个交叉点 $(A_i, B_j)$ ，都代表**机器人 A 在第 $i$ 点的位置**与**机器人 B 在第 $j$ 点的位置**之间的**空间几何距离**（比如末端机械臂在空间里的三维欧氏距离）。

### 2. 画一条“对齐路径”（Warping Path）

DTW 的目标，是从左下角 $(A_1, B_1)$ 走一条线到达右上角 $(A_3, B_5)$ 。

这条路径必须遵守 **3 个物理规则**：

1. **起点与终点绑定**：动作的开头必须对齐（ $A_1$ 对 $B_1$ ），结尾必须对齐（ $A_3$ 对 $B_5$ ）。
2. **不能倒流（单调性）**：时间只能往前走，不能倒退回去匹配。
3. **不能漏掉（连续性）**：每一步只能**往右**、**往上**或者**往右上**走一格，不能隔空跳跃。

```
往右上走 (↘)  --->  A 和 B 同时往前走一步（正常节奏）
往右走   (→)  --->  A 往前走，B 停在原地（B 做得慢，A 在等待/压缩）
往上走   (↑)  --->  B 往前走，A 停在原地（A 做得慢，B 在等待/压缩）

```

假设我们找到的一条最佳路径是：

`(A1, B1) -> (A1, B2) -> (A2, B3) -> (A3, B4) -> (A3, B5)`

这就是长短不一的解法：

- ** $A_1$ ** 顺次去和 ** $B_1, B_2$ ** 比较（说明 B 在动作开头比 A 慢，A 的第一帧被“拉伸”去匹配了 B 的前两帧）。
- ** $A_3$ ** 顺次去和 ** $B_4, B_5$ ** 比较（说明 B 在结尾又变慢了）。

### 3. 如何找到“最佳路径”？

网格上可以走出来的路径有成千上万条，哪条才是对的？

**踩过的格子算出的空间距离之和最小的那条路径，就是最佳路径。**

计算方法非常直观（从起点往终点逐格累加）：

> **当前格子的最小总代价 = 当前格子的空间距离 + min(左边格子的总代价, 下边格子的总代价, 左下格子的总代价)**
这个“递推”过程保证了你最终走出来的总累加距离是理论上可能的**绝对最小值**。

## 三、 一个超简单的计算全过程演示

我们用一组具体数据把这个过程走一遍。

- **机器人 A 的轨迹（3 个点）**： $A = [1, 3, 5]$
- **机器人 B 的轨迹（4 个点）**： $B = [1, 2, 4, 5]$

> 这两条轨迹数值形状一模一样（都是递增），但 B 中间多了一个点 $2$ ，所以长度不一致。

#### 第一步：算出所有点对点的空间绝对差值（构建空间距离矩阵）

把每个 $A_i$ 和 $B_j$ 相减取绝对值：

|  | $B_1=1$ | $B_2=2$ | $B_3=4$ | $B_4=5$ |
| --- | --- | --- | --- | --- |
| ** $A_1=1$ ** | **0** | 1 | 3 | 4 |
| ** $A_2=3$ ** | 2 | **1** | **1** | 2 |
| ** $A_3=5$ ** | 4 | 3 | 1 | **0** |

#### 第二步：计算累积距离矩阵（找累加和最小的通路）

从左下角 $(A_1, B_1)$ 按照规则累加：

1. ** $(A_1, B_1)$ **：距离就是 $0$ 。
2. **第一行 / 第一列**只能直线走：
  - $(A_1, B_2) = 0 + 1 = 1$
  - $(A_1, B_3) = 1 + 3 = 4$
  - $(A_2, B_1) = 0 + 2 = 2$ …
3. **填满整个矩阵**：

|  | $B_1$ | $B_2$ | $B_3$ | $B_4$ |
| --- | --- | --- | --- | --- |
| ** $A_1$ ** | **0** | 1 | 4 | 8 |
| ** $A_2$ ** | 2 | **1** | **2** | 4 |
| ** $A_3$ ** | 6 | 4 | 2 | **2** |

#### 第三步：得到终点的累积距离 & 归一化

- 右上角 $(A_3, B_4)$ 最终算出的**累积 DTW 总距离是 $2$ **。
- **最佳对齐路径为**： $(A_1, B_1) \rightarrow (A_2, B_2) \rightarrow (A_2, B_3) \rightarrow (A_3, B_4)$ 。
  - 可以看到，机器人 A 的 $A_2(3)$ 同时匹配了 B 的 $B_2(2)$ 和 $B_3(4)$ ，成功消除了 B 轨迹多出一个中间点带来的影响！

#### 消除长度差异（归一化）

因为两条轨迹分别长 3 和 4，最佳路径一共踩了 4 个格子。

如果不做处理，**越长的轨迹踩的格子越多，累加出来的距离天然就会偏大**。

所以最后通常会除以**对齐路径的总步数（或两轨迹长度之和）**：

$$
\text{归一化 DTW 距离} = \frac{\text{总代价}}{\text{路径步数}} = \frac{2}{4} = 0.5
$$

这个 **0.5** 就是最终用来评估这两条机器人轨迹相似度的指标。

## 四、 总结：DTW 在机器人轨迹评估中的优缺点

| 优点 | 局限与工程对策 |
| --- | --- |
| **容忍时序变异**：完美解决机器人运动速度不同、中间有停顿、采样频率不一致的问题。 | **计算量随长度剧增**：原生的算法复杂度是 $O(N \times M)$ 。*工程解法：使用 FastDTW 算法，或者给网格加上约束（只允许在对角线附近一定范围内搜索）。* |
| **支持多维数据**：可以直接计算机械臂 6 个关节角构成的向量，或者空间 `[x, y, z]` 坐标。 | **容易误配非物理动作**：如果时间拉伸太夸张，可能把“开头的抬手”强行匹配给“结尾的放手”。*工程解法：设定限制，规定一条帧最多只能拉伸匹配 $W$ 个时间步。* |
