POC（画面显示序号）是视频帧在屏幕上播放的“排队号码牌”。

在现代视频编码（如 H.264 / H.265）中，为了提高压缩效率，画面的解码顺序（Decoding Order）与显示顺序（Display Order / Presentation Order）并不一致（参见[视频编码中的B帧I帧P帧](视频编解码/视频编码中的B帧I帧P帧.md)）：

- **I 帧（关键帧）**：自己独立成画。
- **P 帧（前向预测帧）**：参考前面的帧。
- **B 帧（双向预测帧）**：既参考前面的帧，又参考后面的帧

因为 B 帧需要“未来的帧”来计算差异，编码器必须先把未来的帧解出来存进缓存池（DPB, Decoded Picture Buffer）。

```text
实际播放顺序 (POC):   0 (I)  ->  1 (B)  ->  2 (B)  ->  3 (P)
底层解码顺序:         0 (I)  ->  3 (P)  ->  1 (B)  ->  2 (B)
```

POC 的核心职能有两个：

1. **告诉播放器渲染顺序**：无论解码器按什么鬼魅顺序吐出图像，播放器只要按 POC 从小到大（0, 1, 2, 3…）渲染即可。
2. **计算参考运动矢量**：当 B 帧进行运动补偿时，需要用 POC 的相对距离来按比例推算像素位移。
