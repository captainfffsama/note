## RLinf 项目架构深度分析

### 一、总体分层架构

RLinf 采用 **Macro-to-Micro Flow (M2Flow)** 设计范式，将用户定义的高层逻辑工作流（宏观）自动映射为物理执行计划（微观），整个框架分为以下 **七层**：

```
┌──────────────────────────────────────────────────────────────┐
│               应用层 (Application Layer)                       │
│   examples/ 入口脚本 + Hydra YAML 配置                        │
└──────────────────────────────────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│               运行器层 (Runner Layer)                          │
│   EmbodiedRunner / AsyncEmbodiedRunner / ReasoningRunner      │
│   AgentRunner / SFTRunner / EvalRunner                        │
│   职责：训练循环编排、Worker通信拓扑、权重同步、检查点保存      │
└──────────────────────────────────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│               Worker 执行层 (Execution Layer)                  │
│  ┌────────────┐ ┌──────────────┐ ┌────────────┐ ┌─────────┐  │
│  │Actor Worker│ │Rollout Worker│ │ Env Worker │ │ Reward  │  │
│  │(FSDP/Mega) │ │(HF/SGLang)  │ │(Gym接口)   │ │ Worker  │  │
│  └────────────┘ └──────────────┘ └────────────┘ └─────────┘  │
└──────────────────────────────────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│           通信与调度层 (Scheduling & Communication)            │
│   Channel（异步队列）· WorkerGroup · Cluster · Placement      │
└──────────────────────────────────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│               算法层 (Algorithm Layer)                         │
│   注册器模式：advantages / losses / rewards                   │
│   支持 PPO, GRPO, SAC, DPO, Reinforce++ 等                   │
└──────────────────────────────────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│               模型层 (Model Layer)                             │
│   18+ 策略模型：OpenPI, GR00T, OpenVLA, Flow, MLP, CNN…     │
│   BasePolicy 抽象基类 + 注册器动态加载                        │
└──────────────────────────────────────────────────────────────┘
                             ▼
┌──────────────────────────────────────────────────────────────┐
│               环境层 (Environment Layer)                       │
│   18+ 环境：ManiSkill, LIBERO, IsaacLab, RealWorld Franka… │
│   工厂函数 get_env_cls() 动态加载                             │
└──────────────────────────────────────────────────────────────┘
```

### 二、关键模块抽象

#### 2.1 配置系统 ([config.py](file:///data/workspaces/RLinf/rlinf/config.py))

- **SupportedModel**：冻结数据类，注册所有支持模型（18+ 种），支持 `register()` 动态扩展
- **SupportedEnvType**：枚举类，注册所有环境类型
- **validate_rollout_cfg() / validate_cfg()**：配置校验函数
- 使用 Hydra 进行配置组合与覆盖

#### 2.2 调度系统 ([rlinf/scheduler/](file:///data/workspaces/RLinf/rlinf/scheduler))

| 组件 | 职责 |
|------|------|
| **Worker** | Ray remote actor 抽象基类，自动设置分布式环境变量（MASTER_ADDR/RANK 等） |
| **WorkerGroup** | Worker 集合管理器，支持批量调用与选择性执行 |
| **Channel** | 分布式异步 FIFO 队列，支持 put/get/get_batch，自动选择通信后端（CUDA IPC/NCCL） |
| **Cluster** | 集群资源视图，管理节点/GPU 拓扑 |
| **Placement** | GPU 放置策略（Collocated/Disaggregated/Hybrid），决定每个组件运行在哪里 |

#### 2.3 Runner 层 ([rlinf/runners/](file:///data/workspaces/RLinf/rlinf/runners))

Runner 是训练循环的核心驱动器：

- 创建 Channel 连接拓扑
- 编排 Worker 启动顺序
- 控制权重同步频率
- 管理检查点保存与恢复

#### 2.4 Worker 类型

| Worker 类型 | 核心方法 | 说明 |
|------------|---------|------|
| **Actor** | `run_training(channel)` | 策略训练（损失计算、梯度更新） |
| **Rollout** | `generate(in_chan, out_chan)` | 策略推理（动作生成） |
| **Env** | `interact(env_chan, rollout_chan, …)` | 环境交互循环 |
| **Reward** | `compute_rewards(in_chan, out_chan)` | 奖励计算 |

#### 2.5 算法层 ([rlinf/algorithms/](file:///data/workspaces/RLinf/rlinf/algorithms))

采用 **注册器模式**：

```python
@register_advantage("gae")     # 优势函数注册
@register_policy_loss("ppo")   # 损失函数注册
```

统一 API：`calculate_adv_and_returns()` / `policy_loss()` 根据配置自动分发。

#### 2.6 模型层 ([rlinf/models/](file:///data/workspaces/RLinf/rlinf/models))

**BasePolicy 抽象基类**：

```python
class BasePolicy(nn.Module, ABC):
    class ForwardType(Enum):
        ACTION / ACTION_AND_VALUE / LOGPROBS
    
    @abstractmethod
    def forward(self, images, texts=None, mode=ForwardType.ACTION)
```

#### 2.7 环境层 ([rlinf/envs/](file:///data/workspaces/RLinf/rlinf/envs))

工厂模式动态加载：`get_env_cls(env_type)` → 返回 Gym 兼容环境类。

### 三、模块间协作机制

**核心协作模式**：Runner 通过 Channel 连接 Worker，形成数据流水线。

```
EnvWorker ──env_channel──▶ RolloutWorker ──rollout_channel──▶ ActorWorker
    ▲                           │                                  │
    └───── actions (通过env_channel返回) ─────┘                     │
                                                                   │
    权重同步 (actor → rollout，定期广播) ◀──────────────────────────┘
```

关键机制：

1. **Channel 异步通信**：Worker 间无需直接地址，通过命名 Channel 解耦
2. **权重同步**：Actor 定期将训练好的权重广播给 Rollout（WeightSyncer）
3. **WorkerGroup 批量调度**：同类 Worker 统一管理，支持 DP 并行
4. **Handle 异步等待**：所有远程操作返回 Handle，支持非阻塞执行

### 四、关键接口签名

```python
# Channel API
Channel.create(name, maxsize=0) → Channel
channel.put(data, key=None, async_op=False)
channel.get(key=None, async_op=False)
channel.get_batch(target_weight)

# Worker 核心
Worker.create_group(cfg, placement) → WorkerGroup
worker_group(func_name, *args) → Handle
handle.wait() → result

# Runner
runner.init_workers()
runner.run()  # 主训练循环

# BasePolicy
policy.forward(images, texts, mode) → actions / (actions, values) / logprobs
```

### 五、Franka Peg Insertion + OpenPI π₀.₅ + SAC 完整训练流程

以下以真机 Franka 执行 Peg Insertion 任务为例，梳理端到端流程：

#### Phase 1：环境准备

```bash
# 获取目标末端位姿
python -m toolkits.realworld_check.test_franka_controller
# 命令 getpos_euler → [x, y, z, rx, ry, rz]

# 下载预训练 ResNet10 编码器
hf download RLinf/RLinf-ResNet10-pretrained
```

#### Phase 2：数据采集（RLPD 示范数据）

```bash
bash examples/embodiment/collect_data.sh
```

通过 SpaceMouse 人工遥操作完成 N 条成功轨迹 → 存入 `logs/{timestamp}/demos/`

#### Phase 3：集群启动（双节点）

```bash
# 节点0（GPU训练/推理）
export RLINF_NODE_RANK=0
ray start --head --port=6379

# 节点1（Franka控制）
export RLINF_NODE_RANK=1
ray start --address='<head_ip>:6379'
```

#### Phase 4：训练启动

```bash
bash examples/embodiment/run_realworld_async.sh realworld_sac_flow_image
# → python examples/embodiment/train_async.py --config-name realworld_sac_flow_image
```

**启动流程**：

1. Hydra 加载配置 → 检测 `loss_type=embodied_sac` → 选择 `AsyncEmbodiedRunner` + `AsyncEmbodiedSACFSDPPolicy`
2. 创建 `Cluster` → `HybridComponentPlacement`（Actor/Rollout → 4090 节点，Env → Franka 节点）
3. 创建并启动 WorkerGroup（Actor、Rollout、Env）
4. Runner 初始化 Worker 并进入训练循环

#### Phase 5：异步训练循环

```
┌─── Franka 节点 ───┐          ┌─── GPU 节点 ──────────────────────┐
│                   │          │                                    │
│  AsyncEnvWorker   │◀════════▶│  AsyncMultiStepRolloutWorker      │
│  - reset/step     │ channel  │  - 策略推理 (Flow Matching)        │
│  - 观测：19D状态   │          │  - 4步去噪生成动作                 │
│    + 128²腕部图像  │          │                                    │
│  - 动作：6D笛卡尔  │          │  AsyncEmbodiedSACFSDPPolicy       │
│                   │          │  - Replay Buffer 接收轨迹          │
│                   │          │  - 采样256条训练                    │
│                   │          │  - Critic更新(×4) + Actor更新(×1)  │
│                   │          │  - 温度α自适应                     │
│                   │          │  - 目标网络软更新(τ=0.005)         │
└───────────────────┘          └────────────────────────────────────┘
```

**SAC 训练细节**：

- **Critic 损失**：双 Q 网络 TD 误差，取 min 防高估
- **Actor 损失**：最大化 `min_i Q(s,a) - α·log π(a|s)`
- **温度 α**：Softplus 参数化，目标熵 = -3（`-action_dim/2`）
- **数据混合**：50% Demo Buffer (RLPD) + 50% 在线 Replay Buffer
- **训练频率**：每个环境交互后执行 30 步梯度更新，Critic:Actor = 4:1

#### Phase 6：关键配置参数

| 类别 | 参数 | 值 | 说明 |
|------|------|-----|------|
| 集群 | `num_nodes` | 2 | GPU 节点 + Franka 节点 |
| 算法 | `gamma` | 0.96 | 折扣因子 |
| 算法 | `tau` | 0.005 | 目标网络软更新 |
| 算法 | `update_epoch` | 30 | 每交互一次训练 30 步 |
| 算法 | `critic_actor_ratio` | 4 | Critic 训练更频繁 |
| 模型 | `denoising_steps` | 4 | Flow Matching 去噪步数 |
| 模型 | `num_q_heads` | 10 | SAC Q 函数头数量 |
| 训练 | `micro_batch_size` | 256 | 从 Buffer 中采样 256 条 |
| Buffer | `cache_size` | 200 | 内存缓存 200 条轨迹 |

#### Phase 7：输出与监控

- **检查点**：`checkpoints/global_step_N/`
- **TensorBoard**：`env/reward`、`env/success_once`、`train/sac/critic_loss`、`train/sac/actor_loss`、`train/sac/alpha`
- **训练预期**：1-2 小时达到高成功率

### 六、核心设计模式总结

| 设计模式 | 应用位置 | 优势 |
|---------|---------|------|
| **M2Flow** | Runner↔Worker | 用户关注逻辑流，框架处理物理调度 |
| **注册器模式** | 算法/模型/环境 | 高度可扩展，新增组件仅需注册 |
| **Channel 模式** | Worker 间通信 | 解耦 + 异步 + 自动后端优化 |
| **WorkerGroup** | 同类 Worker 管理 | 统一批量调度、DP 并行 |
| **Placement 策略** | 资源分配 | 支持异构集群、灵活布局 |
